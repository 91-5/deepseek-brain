## Context

deepseek-brain 当前是 **Windows-only**，且是硬性限制而非技术必然：

- `package.json` 声明 `os: ["win32"]` —— 非 Windows 平台安装即被拒绝。
- `src/transports/chrome-detect.ts`（53 行）的 Chrome 探测只有 6 条 Windows 硬编码路径，函数名 `windowsChromeCandidates` / `detectWindowsChrome` 直接编码了平台假设。
- `README.md` 把「Windows only」写成**范围决定，不是待办**，并声明「跨平台探测、snap/Flatpak 路径、无显示器远程场景全部不实现」。
- CI 只跑 `windows-latest`。

项目的核心价值（把 DeepSeek 网页版包装成 OpenAI 兼容 API）与平台无关，被 `os` 字段无谓地挡在 Windows 之外。本次改造放开这个限制并扩充探测表。

**上游调研已完成两路：**
1. **源码级调研**：对比 puppeteer / chrome-launcher / karma-chrome-launcher / playwright 四家的探测实现，核实各平台真实安装路径，确认 `accessSync(X_OK)` 是唯一三平台通用的探测原语。详见 spec §10。
2. **架构可行性评估**：得出本任务最关键的约束——**headless Linux 上首登流程物理上不成立**，因此「全系统兼容」必须按验证程度诚实分级，而不是宣称全平台。

设计规格：`docs/superpowers/specs/2026-10-02-deepseek-brain-cross-platform-design.md`
