# `.tasks/legacy/` — 历史证据，不参与 lint

这个目录里的东西**不参与 `lint_cards.py` 的 lint**，但其中的 id **仍然会与
`verdicts/` 配对**（`tools/lint_cards.py` 的 `_legacy_card_ids()` 会从本目录
`*.md` 的文件名里提取 `NS-YYYYMMDD-NNN` 形式的 id）。

## 为什么需要这个目录

2026-10-02 做过一次卡片改名手术（002 与 verdict id `XJ-20261002-002` 撞号），
此后卡的 id 与历史 verdict 的 id **不再一一对应**。id 会变，证据不该跟着消失，
所以历史材料放这里，而不是删掉。

## 两种文件，别混淆

| 文件 | 是什么 |
|---|---|
| `REVIEW-XJ-20261001-001.md` | **真正的评审记录**，当时写的，只是已不参与 lint |
| `XJ-20261002-00N.verdict-index.md` | **索引桩**，不是评审。verdict json 还在，但写它的评审文档已丢失，桩只负责交代那一轮判了什么、证据缺口在哪 |

索引桩里**不写 verdict 计数以外的内容**——blocker 的具体内容已无法复原，
凭计数反推就是编造。

**索引桩也不复原 verdict 的 `evidence` 块。** 计数不是全貌——以 `XJ-20261002-002`
为例，它的 evidence 块里就藏着 5 条未计入的 TODO，而 verdict 报的是
「1 blocker / 0 conditions」。所以**verdict json 本身也不是完整证据**，
只是一份结论摘要。要复原那些内容，只能找到当年的原始评审文档，而它已丢失。

## 归档去哪

已 `CLOSED` 的任务卡也从 `.tasks/` 顶层移到这里（PROTOCOL §8 的「一个工作日内
归档或删除」）。移这里而不是 `archive/` 是有原因的：linter 只扫顶层 `*.md`，
移进 `archive/` 会让对应的 verdict 变成孤儿；而 `legacy/` 既不参与 lint、
又能保住配对。**别把新东西放进 `archive/`。**

## 什么时候能清掉

本目录是历史证据，按 §8 的反膨胀规则**不设 TTL**——它不是待办，是记录。
只有当某个 id 的 verdict 与评审文档都确认无价值时，才连同 verdict 一起删。
## 已知残留：4 条 `VERDICT_WITHOUT_REVIEW` 消不掉，也不该消

清理后 board 上仍有 4 条 `VERDICT_WITHOUT_REVIEW`（`DSB-20261002-001` /
`-003` / `-004` / `-005`）。它们的成因是**卡片 id 与 verdict id 在 2026-10-02
的改名手术后不再一一对应**：

| 卡 | 它的评审实际在哪 |
|---|---|
| `DSB-20261002-003` | `DSB-20261002-006.verdict.json`（为避开撞号而改成 006） |
| `DSB-20261002-004` | `XJ-20261002-001` / `XJ-20261002-002`（第 1、2 轮） |
| `DSB-20261002-005` | `XJ-20261002-003`（第 3 轮） |
| `DSB-20261002-001` | 同上三轮（该卡的实现就是被评的那次变更） |

`lint_cards.py` 按 id 配对（`card_ids - verdict_ids`），所以这 4 条**必然命中**。

**为什么不消**：唯一的消法是造 4 个同 id 的 `verdict.json`，那是**伪造评审证据**
——比一条 warning 坏得多。改文件名同理：verdict 的 id 是证据的一部分，改名即改证据。

所以这里选择**记下来**。这 4 条 warning 是真实的债务提示，但它们提示的不是
「缺评审」，而是「评审发生过、id 变了」——后者由本目录的索引桩与各卡的
`## 补记` 承担可追溯性。

**如果 agent-covenant 将来想让它可机检**，正确做法是给 pairing 支持显式的
id 别名映射（例如 verdict 里加 `supersedes_cards: [...]`），而不是让人去改名或补假文件。
这属于协议变更，需要按 §6.2 先评审再合。
